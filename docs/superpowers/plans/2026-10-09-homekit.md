# Native HomeKit Implementation Plan

> **As merged:** this was first built as a standalone accessory, then ported onto the HomeSpan bridge already on `main` (Fireplace + Lighter, PR #1). What carried over: the dimmable Fireplace light, `fw::HomeSync` and its tests, HomeSpan owning Wi-Fi and mDNS, the compile-time setup-code check, and `ota_auth.py`. The bridge keeps `main`'s `HOMEKIT_PORT 1201` and accessory layout.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firewatch appears in Apple Home as a dimmable light called "Fireplace" that starts and
stops the scene exactly like `/on` and `/off`, and always shows the scene's real state.

**Architecture:**
- **HomeSync:** a pure `fw::HomeSync` class in `firecore`, tested on the host. It decides when
  a Home write should become a scene command, and when the device's state should be pushed to
  Home.
- **homekit module:** a thin `src/homekit.{h,cpp}` that wires HomeSpan 1.9.1 to it.
- **Who owns the network:** HomeSpan takes over Wi-Fi and mDNS. `main.cpp` registers its HTTP
  and OTA services from HomeSpan's Wi-Fi callback.
- **Flash:** a `min_spiffs` partition table makes room for HomeSpan.

**Tech Stack:**
- PlatformIO
- `espressif32@6.9.0` (Arduino-ESP32 2.0.17)
- HomeSpan 1.9.1
- Unity tests on the `native` env, built with w64devkit GCC on Windows

**Spec:** `docs/superpowers/specs/2026-10-09-homekit-design.md`

## Global Constraints

- HomeSpan pinned to exactly `homespan/HomeSpan@1.9.1`. Do not change `platform = espressif32@6.9.0`.
- `board_build.partitions = min_spiffs.csv` (env `esp32`). The first flash after this change must go over USB.
- HomeKit accessory: one `Service::LightBulb` with `On` + `Brightness`, display name "Fireplace", category `Category::Lighting`.
- `HOMEKIT_PORT 51826`. The web page stays on port 80.
- `HOMEKIT_SETUP_CODE` lives in `secrets.h`: exactly 8 digits, not all the same digit, not `12345678` / `87654321`.
- Home on = `fw::Command::On`, Home off = `fw::Command::Off`, routed through the existing `commandQueue`. A Home write whose on/off matches the scene's current on/off sends **no** command.
- Brightness has one setter shared by the web handler and HomeKit, persisted to `Preferences` key `"bright"`.
- Hold window after a Home write: 5000 ms, ended early when the device matches what Home asked for.
- No HomeSpan control pin and no status LED. `BUTTON_PIN` (GPIO0) stays the scene button.
- The render loop on core 1 is untouched. HomeSpan uses `autoPoll()` on core 0.
- Host tools: `C:\Users\Micah\.platformio\penv\Scripts\pio.exe` (call it `pio` below). Host
  tests need `C:\Dev\tools\w64devkit\bin` on PATH (already in the user PATH; prepend it in
  shells started before that).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **"Hey Siri, turn on all the lights" while the TV is showing something else.** The scene is
   already on, so this must not relaunch the fire video over what's playing. Pinned by
   `test_home_write_matching_state_is_not_a_command` (Task 1) and the `power->updated()` gate
   (Task 2).
2. **A Home tap while the TV is asleep or slow to answer.** The network task can block for
   seconds. The Home tile must not flip back to off during that time. Pinned by
   `test_home_write_holds_until_device_catches_up` and `test_hold_expires_and_reports_real_state`.
3. **More than 49 days of uptime.** When `millis()` wraps, the hold window must still expire.
   Pinned by `test_hold_survives_millis_wraparound`.
4. **A setup code HomeSpan rejects.** HomeSpan halts the whole board at boot (`while(1)`),
   which would kill the fire, the button and the web page. Rejected at compile time by
   `static_assert(fw::validSetupCode(...))`. Pinned by `test_setup_code_validation`.
5. **Router down or Wi-Fi slow at boot.** The render loop, button and fade must keep working.
   OTA must not be started before an IP exists. Covered by gating `ArduinoOTA.handle()` on
   `wifiReady` (Task 2), and checked on hardware in Task 3, Step 7.

`firmware/lib/firecore/src/home_sync.h`:

```cpp
#pragma once
#include <cstdint>

namespace fw {

// What Apple Home shows for the Fireplace light.
struct HomeState {
  bool on = false;
  int brightness = 0;  // 0-100

  bool operator==(const HomeState& o) const { return on == o.on && brightness == o.brightness; }
  bool operator!=(const HomeState& o) const { return !(*this == o); }
};

// Keeps Apple Home's view of the scene honest without fighting the person using it. Free of
// I/O so it can be unit-tested:
//  - Anything else that changes the scene (remote, web page, button, the TV's auto-off) is
//    reported to Home.
//  - After Home writes, reports are held back until the device matches or holdMs passes, so
//    the tile doesn't flip back while the network task is busy waking the TV.
//  - A Home write that matches the scene's on/off is not a command: sending On again would
//    relaunch the fire over whatever the TV is showing.
class HomeSync {
 public:
  explicit HomeSync(uint32_t holdMs = 5000) : holdMs_(holdMs) {}

  // Home's view when the accessory is created.
  void seed(HomeState s) {
    shown_ = s;
    holding_ = false;
  }

  // Home now shows `wanted`; the device is at `actual`. Returns true when the scene's on/off
  // must change to wanted.on.
  bool homeWrote(HomeState wanted, HomeState actual, uint32_t nowMs);

  // Returns true when Home must be told `out` (and from then on shows it).
  bool poll(HomeState actual, uint32_t nowMs, HomeState& out);

 private:
  uint32_t holdMs_;
  HomeState shown_;
  bool holding_ = false;
  uint32_t holdStartMs_ = 0;
};

// HomeSpan halts the board at boot on a setup code it rejects, so check it at compile time:
// exactly 8 digits, not all the same digit, and not 12345678 or 87654321.
constexpr bool validSetupCode(const char* s) {
  for (int i = 0; i < 8; ++i)
    if (s[i] < '0' || s[i] > '9') return false;
  if (s[8] != '\0') return false;
  bool allSame = true;
  for (int i = 1; i < 8; ++i) allSame = allSame && s[i] == s[0];
  auto is = [](const char* a, const char* b) {
    for (int i = 0; i < 8; ++i)
      if (a[i] != b[i]) return false;
    return true;
  };
  return !allSame && !is(s, "12345678") && !is(s, "87654321");
}

}  // namespace fw
```

- [ ] **Step 4: Write the implementation**

`firmware/lib/firecore/src/home_sync.cpp`:

```cpp
#include "home_sync.h"

namespace fw {

bool HomeSync::homeWrote(HomeState wanted, HomeState actual, uint32_t now) {
  shown_ = wanted;
  holding_ = true;
  holdStartMs_ = now;
  return wanted.on != actual.on;
}

bool HomeSync::poll(HomeState actual, uint32_t now, HomeState& out) {
  if (holding_) {
    if (actual != shown_ && now - holdStartMs_ < holdMs_) return false;
    holding_ = false;
  }
  if (actual == shown_) return false;
  shown_ = actual;
  out = actual;
  return true;
}

}  // namespace fw
```

```cpp
#include "scene.h"

// Native Apple HomeKit: the scene appears in the Home app as a dimmable light (HOMEKIT_NAME).
// HomeSpan runs in its own task on core 0 and owns Wi-Fi (connect and reconnect) and mDNS.
namespace homekit {

struct Hooks {
  void (*sendCommand)(fw::Command c);
  void (*setBrightness)(int pct);
  bool (*lightsOn)();
  int (*brightness)();
  void (*onWifiConnected)();  // first connection only, after mDNS is up
};

void begin(const Hooks& hooks);
bool paired();

}  // namespace homekit
```

`firmware/src/homekit.cpp`:

```cpp
#include "homekit.h"

#include <HomeSpan.h>

#include <atomic>

#include "config.h"
#include "home_sync.h"

#if __has_include("secrets.h")
#include "secrets.h"
#else
#include "secrets.example.h"
#endif

static_assert(fw::validSetupCode(HOMEKIT_SETUP_CODE),
              "HOMEKIT_SETUP_CODE in secrets.h must be 8 digits, not all the same digit, "
              "and not 12345678 or 87654321");

namespace homekit {
namespace {

Hooks hooks;
std::atomic<bool> isPaired{false};

fw::HomeState actual() { return {hooks.lightsOn(), hooks.brightness()}; }

struct FireLight : Service::LightBulb {
  SpanCharacteristic* power;
  SpanCharacteristic* level;
  fw::HomeSync sync;
  uint32_t lastPollMs = 0;

  FireLight() : Service::LightBulb() {
    const fw::HomeState now = actual();
    power = new Characteristic::On(now.on);
    level = new Characteristic::Brightness(now.brightness);
    sync.seed(now);
  }

  // A write from Home (tile, Siri, scene, automation).
  boolean update() override {
    const fw::HomeState wanted{power->getNewVal() != 0, level->getNewVal()};
    const fw::HomeState current = actual();
    if (level->updated()) hooks.setBrightness(wanted.brightness);
    // Only an actual On/Off write can start or stop the scene; a brightness-only write
    // carries the tile's current on/off, which may be a few ms stale.
    if (sync.homeWrote(wanted, current, millis()) && power->updated())
      hooks.sendCommand(wanted.on ? fw::Command::On : fw::Command::Off);
    return true;
  }

  // Push changes made elsewhere (remote, web page, button, TV auto-off) to Home.
  void loop() override {
    const uint32_t now = millis();
    if (now - lastPollMs < 250) return;
    lastPollMs = now;
    fw::HomeState out;
    if (!sync.poll(actual(), now, out)) return;
    if ((power->getVal() != 0) != out.on) power->setVal(out.on);
    if (level->getVal() != out.brightness) level->setVal(out.brightness);
  }
};

}  // namespace

void begin(const Hooks& h) {
  hooks = h;
  homeSpan.setPortNum(HOMEKIT_PORT)
      .setHostNameSuffix("")  // firewatch.local, not firewatch-XXXXXXXXXXXX.local
      .setWifiCredentials(WIFI_SSID, WIFI_PASSWORD)
      .setPairingCode(HOMEKIT_SETUP_CODE)
      .setWifiCallback([] { hooks.onWifiConnected(); })
      .setPairCallback([](boolean p) { isPaired = p; })
      .setStatusCallback([](HS_STATUS s) {
        if (s == HS_PAIRED) isPaired = true;
        if (s == HS_PAIRING_NEEDED) isPaired = false;
      });
  homeSpan.begin(Category::Lighting, HOMEKIT_NAME, HOSTNAME, "Firewatch");

  new SpanAccessory();
  new Service::AccessoryInformation();
  new Characteristic::Identify();
  new FireLight();

  homeSpan.autoPoll();  // own task, core 0, next to the net and web tasks
}

bool paired() { return isPaired; }

}  // namespace homekit
```

```markdown
## 6. Add it to Apple Home

1. On an iPhone on the same network, open **Home → + → Add Accessory → More options…**. **Fireplace** appears in the list.
2. Pick it, choose **Add Anyway** at the "uncertified accessory" warning, and type the 8-digit `HOMEKIT_SETUP_CODE` from `secrets.h`.
3. Put it in the room with the fireplace. `http://firewatch.local/status` now shows `"homekit":"paired"`.

It's a dimmable light, so "Hey Siri, turn on the fireplace" works, and so do scenes and automations. Siri's "all the lights" commands include it, which turns the TV off or on along with the glow. A command that matches the current state ("turn on" while it's already on) does nothing, so it never interrupts what the TV is playing. Control away from home and automations need a home hub (Apple TV or HomePod), as with any HomeKit device.
```

### Task 3: Flash and verify on the hardware

Needs the user, who swaps between USB and the 5 V supply and uses the Home app.

**Files:** none, unless a fix is needed. Any fix goes back through Task 1's or Task 2's
test/build steps and gets its own commit.

- [ ] **Step 1: USB flash** (user: unplug the 5 V supply, connect USB-C)

Run: `pio device list` and find the CH340 port (it was COM3). Then run
`pio run -e esp32 -t upload --upload-port COM3`.
Expected: `Hash of data verified`, SUCCESS. The partition table at 0x8000 is written along
with the app.

- [ ] **Step 2: Boot log**

Capture 40 s of serial output after an RTS reset: pyserial from the PlatformIO penv
(`python -I script.py COM3 40`), or `pio device monitor` by hand.
Expected:
- the HomeSpan banner shows `Partition: app0` and `Sketch Compiled`
- `HostName: firewatch.local:51826`
- `Starting HAP Server on port 51826`
- `DEVICE NOT YET PAIRED`
- `[wifi] connected 192.168.1.x`
- **no** `WARNING! Internal Free Heap` line
- **no** `PROGRAM HALTED`

- [ ] **Step 3: Network services still work**

Run: `curl -s -m 5 http://firewatch.local/status`
Expected: JSON with `"homekit":"unpaired"`, `"tv":"standby"` or `"on"`, and an empty `lastError`.

- [ ] **Step 4: Pair** (user: back on the 5 V supply, Home app, steps from install.md §6)

Expected: pairing completes. `/status` shows `"homekit":"paired"`.

- [ ] **Step 5: Both directions**

The user and agent take turns, with the agent polling `/status` and the user watching the Home tile:
1. Home tile on → glow fades in, TV wakes, video launches; the tile stays on throughout.
2. Home tile off → glow fades out, TV off.
3. Roku remote power on → the Home tile turns on within about 2 s.
4. Roku remote power off → the tile turns off within about 2 s.
5. Web slider to 30 → the tile shows 30%. Home slider to 70 → `/status` shows `"brightness":70`.
6. With the scene on, ask Siri "turn on the fireplace" → nothing restarts. `lastEvent` is
   unchanged, and no `[roku] launch` appears in the serial log if it's connected.

- [ ] **Step 6: OTA**

Run: `pio run -e esp32-ota -t upload`
Expected: SUCCESS over Wi-Fi. Afterwards `/status` uptime resets, and the Home tile shows the
correct state again within about 30 s.

- [ ] **Step 7: Flicker and Wi-Fi-loss sanity check**

- Check: does the fire look the same as before? There should be no stutter while toggling from
  Home or during pairing traffic.
- Optional, if the user is willing: power-cycle the router (or the board with the router off).
  The button should still toggle the glow while Wi-Fi is down, and Home should catch up after
  the reconnect.

Update `docs/install.md` with anything learned on the hardware, then commit. Report the
